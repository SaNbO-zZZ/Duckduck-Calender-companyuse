# 鸭鸭日历 · 本轮本地修改审查

唯一应用源文件：[鸭鸭日历.html](/Users/xz/Sanbo/Codex/Company/company_use_calendar/鸭鸭日历.html)。本轮未部署，也没有改动飞书正式应用。全部应用代码仍在这个 HTML 内。

## 已完成

- 修正雪人围巾的风向，跟随同一带符号的风速，鸭鸭左右朝向也保持一致。
- 强风基础风速不再提前截满姿态；60 km/h 对应 0.75 档，阵风可继续到 1 档。风是独立环境，晴天、雨天、雪天可分别叠加强风。
- 窄屏按 CSS 可用宽度安排九只鸭鸭，DPR 只决定画布分辨率；移除按比例重叠挤压的兜底。手机保留前后两排。
- 鸭鸭 2D 上下文丢失、精灵画布创建失败时保留 PNG 静态鸭鸭，恢复主画布后清理缓存并重绘。前景和备用天空 2D 失败时也不会阻断表单与正文。
- 云由规则球团改为连续湍流密度、不对称轮廓及厚度明暗。太阳遮挡与云绘制继续共享透明度采样。
- 日历月份和“今天”改用北京时间动态生成，跨日更新；不再固定 8 号。选择演示日期时显式标记“演示”，真实今天仍按北京时间标记。
- 新增“天才总是晚到”与“我先去拯救世界了”，各自打开独立内容的弹窗。前者显示当前时间、今天预计到达时间、Mentor、人事；后者显示当前时间、Mentor、人事。
- 请假表单仅保留类型、开始/结束日期与时刻、Mentor、人事；删除事项、申请小时、交接说明。
- 固定人事为 Mia，仅通知，无审批。三类表单都有可读的本地通知预览。
- 320 像素下缩小标题、分行显示日期与时刻，避免单字换行与日期被截断；弹窗可滚动，背景不跟随滚动。

## 验证与边界

- JavaScript 语法检查通过，浏览器未发现脚本或着色器错误。
- 实际浏览器检查了 1440 × 900、320 × 844、360 × 844、390 × 844；320/360 下正文无横向溢出。
- 执行源文件中的实际布局函数：320/360/390/720/1440 × DPR 1/2/3 共 15 组，同排间距满足约束且不进入挤压兜底。
- 故障注入测试：主 2D 上下文丢失后仍保留九只 PNG 鸭鸭；恢复后回到 Canvas；精灵 2D 创建失败也保留九只静态鸭鸭。这是函数级注入及浏览器强制静态图模式验证，并非实际制造 GPU 故障。
- 检查了 1854 组美术配置，均可生成非空像素。阵风前后精灵姿态缓存键不同，基础风速不再提前饱和。
- 浏览器验证了迟到时间早于 10:00/当前时间时不可提交；请假结束早于开始会提示错误；三种表单内容独立重置，Mia 不可编辑。
- 天气仍为演示预设。Mentor 目前是本地姓名输入，未接真实飞书通讯录；“预览通知”不会提交记录或发消息。上线接入属于后续阶段。
- 云仍采用性能受控的二维体积光照近似，尚不能当作 iOS 系统天气的真实体积渲染。请重点审查云的厚度、边缘与遮阳过程是否符合视觉目标。
- 窄屏浏览器模拟不代表手机硬件性能验证；仍需在飞书手机端真机复核。
- 截图是静态审查帧，不能用于判断阵风节奏。请打开同一个 HTML，选择“强风”并保持“减少动态：跟随系统”来审查运动；系统开启减少动态时会保持静态。

## 如何审查

双击 HTML 可在本地浏览器打开。顶部选择天气、风等级、风向、清晨/正午/傍晚/夜间；“隐藏审查栏”查看纯页面，按 Esc 恢复。点击三个出勤按钮查看弹窗。“手机宽度”使用同一份 HTML 的 390 像素框内预览，非另一个应用文件。可用 `?phone=1&width=320` 或 `360` 审查更窄的框。

下面的晴天、雨雪及风向对照截图采用静态审查模式，便于比较稳定布局；第 16 张同时使用模拟备用天空和 PNG 鸭鸭。
