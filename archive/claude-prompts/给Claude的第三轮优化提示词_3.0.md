## 4. 鸭鸭的美术风格是硬性要求

用户要求完全延续这套内部表情包的美术风格。现有参考的关键特征是：

- 白色/奶白色的梨形身体，夸张的可伸缩长脖子，明显的大橙色扁嘴，橙色蹼足。
- 小黑眼、半眯眼和夸张但略呆的表情，保持原有幽默气质。
- 深炭色/暖深色的粗像素轮廓，少量浅灰/奶白分块阴影。
- 大像素块、有限色板、简洁且可在小尺寸辨认的姿势。
- 保持像素边缘；服装、帽子、伞、杯子、鱼竿等新增道具也使用同样的像素颗粒、轮廓粗细和色板关系。

不得替换成通用 🦆 emoji、橡皮鸭、黄鸭、圆润矢量吉祥物、平滑描边插画、3D 鸭子或照片。不能只是画九个同款鸭头再换帽子，就称为九种独立动作。

可以复用原有无字动作和透明帧；现有素材缺少钓鱼、喝咖啡、雨衣等天气动作，必须在相同画风下补齐。新增姿势须改变身体/翅膀/脖子/嘴的合理关系，让道具真正被持握或使用，而不是悬浮在鸭子旁边。

采用透明 PNG 精灵、内嵌像素资源或符合原风格的像素绘制均可，但成品必须与原素材并排比较：角色轮廓、嘴身比例、眼睛、线条、调色和动作辨识度一致。不要仅凭“也是白鸭”宣布匹配。

不直接使用带文字表情作为装饰，不带进白色缩略图背景或品红底。检查透明边缘，避免品红毛边、黑底块、过度平滑和姿势切换时的脚底跳动。像素绘制/缩放关闭非必要插值。

如果现有工具不足以补齐同风格的新动作，明确说明哪些没有做出来；不得把占位鸭子或不匹配的画风伪装成最终实现。

## 6. 九只独立角色：有约束的随机，而不是每帧乱选

建立九个稳定的角色槽位/身份，统一接入已有天气状态。每只的动作、表情、服装与道具有独立选择，但选择必须符合天气。

- 每个基础天气族准备不少于九种可区分的主动作，建议 12 种以上以便随机选择。
- 同一场景九只的主动作采用不重复抽取。不得九只同时做一个动作，也不要用九种颜色的伞冒充九种动作。
- 不同帧阶段只属于动画相位，不算不同主动作。站着眨眼、站着歪头、站着换帽子不能凑成九项独立活动。
- 随机选择应在场景建立、合理的时间阶段变化或审查“重新随机”时进行；不要每帧或每次轻微阵风重新抽样。
- 使用可复现的种子，审查时能固定种子并主动重抽。相同种子和条件得到相同组合，便于前后对比。
- 每只可以有独立动画相位、休息间隔与节奏，避免同步眨眼、同步挥翅、同步弹跳。
- 天气切换后，动作与服装平滑适应；维持九个身份和场景位置，避免全员瞬间换位。切换过程中不累积新实例，不变成十八只。
- 改变风速/风向时，保留基础天气与正在进行的活动，优先调整持物、姿态、衣物和道具的风反应，不重新变成另一种天气。
- 时间变化影响适用活动和气氛：清晨更清醒/舒展，正午遮阳或午睡，傍晚收拾与暖光，夜间安静活动。不能整夜仍戴太阳镜晒太阳。

建议用一个清楚的动作数据表记录 `id / actionFamily / compatibleWeather / timePhase / outfit / props / windResponse / frames / anchor` 等；这是实现建议，不要求照抄字段名。动作库与随机选择都在唯一 HTML 内。

## 8. 继续改善天气真实感，保留业务可读性

### 云与遮阳

- 本轮重点解决大片柔化白斑/涂抹感。改善分层的云体、明暗面、自然云缘和远近尺度；不是单纯加对比、加噪点或增加模糊。
- 云的受光方向与太阳方位一致，清晨/傍晚可有克制暖边，正午避免过度发光。
- 多云保持云间的蓝天空隙；阴天有较连续云盖；开启强风不能增加云量或把天空改灰。
- 同一套实际移动云场控制太阳本体、光晕、光斑和局部天空亮度的遮挡与恢复，不使用独立随机闪烁。
- 不要求必须使用重型体积光线步进；选用受控成本的层次、形状和光照方法，以实际完整画面为准。

### 日照与时间

- 地点固定合肥市瑶海区，代表坐标 `31.8696, 117.3154`，北京时间 `Asia/Shanghai`。
- 保留连续的日期、时间、季节计算与清晨/正午/傍晚/夜间审查入口。
- 屏幕投影可以做视觉构图调整，但必须连续；不把太阳固定在一个角落，也不随鸭子位置跳动。
- 正午太阳、暖色霞光和多云遮阳在含九只鸭子的正常页面仍应可感知；不挤掉天空空间。
- 鸭子与道具可以有克制的整体环境明暗、冷暖与接触阴影，保持像素色板辨识，不把它们套上模糊滤镜或强渐变。

### 雨雪与接触

- 小雨清楚但稀疏，大雨更密更长，暴雨更连续；主要靠雨丝区分，玻璃水珠保持默认关闭/可选。
- 雨向下落、拖尾在运动后方，有风再倾斜。卡片击打、水花弹出及重力回落继续成立。
- 小雪薄且零散，中雪较多，大雪更连续；积雪上限明确，不遮挡字和标识。
- 鸭子的雨棚/伞/地面支撑与天气有合理接触关系。可以少量增加伞边滴水、脚边小水花、帽顶薄雪，但不需要每根雨丝都做碰撞或真实流体模拟。
- 背景雨丝不要显得直接穿过不透明伞面或遮雨棚；使用局部遮挡/分层等轻量办法即可。

## 9. 统一调度、减少动态与故障降级

新增九只鸭子必须纳入已有生命周期，避免“天气停了，九个 GIF 还在动”。

- 优先使用可统一控制的逐帧精灵或轻量像素绘制；不要九只各建一套 RAF/定时器、独立全屏 canvas 或大量昂贵滤镜。
- 天气渲染目标维持桌面约 60 FPS、手机约 30 FPS；鸭子逐帧可以约 6–12 FPS，姿态/受风插值可以更平滑。使用经过时间决定帧，不绑定屏幕刷新率。
- 带帽子、围巾、伞等局部动画有统一粒子/绘制预算，不让新增细节抵消之前的性能改善。
- 继续限制 DPR、总像素预算、粒子数量和资源尺寸。小尺寸角色不用内嵌数十张巨型原始帧图；去除不必要透明边界时保持统一角色锚点。
- 只内嵌实际用到的资源，不把整个 ZIP/base64 打进 HTML。说明最终文件体积及增长原因。
- 遵循系统减少动态偏好的初始值及运行中变化。九只鸭子保留各自符合天气的代表性静态姿态，停止非必要逐帧、摆动、随机切换与阵风运动。
- WebGL 不支持/丢失/持续低帧率时，天空静态备用仍有可辨天气等级，九只鸭子仍完整显示；不能降级后只剩灰色渐变或鸭子全部消失。
- 如果前景画布也不可用，采用同文件内资源的静态 DOM 图像等轻量后备，避免依赖 WebGL 才有鸭子。
- 后台暂停；返回后平滑恢复，不集中补播帧/喷粒子。重复切换天气/风、缩放、进入静态、导航返回后无重复实例、循环、监听器或资源泄漏。
