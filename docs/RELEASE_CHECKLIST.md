# 飞书发布检查

1. 从 `main` 建分支完成修改，PR 中说明问题、修复和验证结果；合并后记录实际 commit SHA。
2. 运行受影响的测试、类型检查、Lint 与生产构建。视觉修改核对桌面、窄屏、减少动态；业务修改核对登记人与通知角色。
3. 在飞书妙搭发布时记录 release ID 和状态，并从普通员工视角检查企业入口。不要用“API 已发送”替代“收件人已阅读”的结论。
4. 核对线上代码确实对应被标记的 commit，再打稳定 Tag 并推送；Tag 不自动等于飞书发布。
5. 若发现回归，优先回退飞书发布或在 `main` 上 `git revert`，保留审计历史；在工程记录中补充影响范围与恢复结果。

天气数据源目前处于合肥站实况试运行阶段，其网站内部 JSON 接口的长期授权与稳定性需另行核实。不要把试运行视为永久服务承诺。
