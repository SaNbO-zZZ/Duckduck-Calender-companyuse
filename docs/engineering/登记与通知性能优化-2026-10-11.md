## 本次改动

- Mentor、人事通知在登记写入成功之后并行发送，各自持有发送领取和持久化状态；同一人只发一次。某一位发送失败不会阻止另一位。
- 增加只读登记进度接口，严格限定当前登录登记人，禁止缓存；页面每次只发起一个进度查询，不重复提交和不重发通知。
- 多维表格登记及数据库记录确认保存后立即显示“已登记”，可以关闭表单；原提交请求继续完成通知和状态回写。通知尚未确认时明确显示“正在发送”，不会提前宣称通知成功。
- 两位通知都确认后页面可显示完成，不再等待多维表格通知状态镜像回写。服务端仍 await 全部操作，没有新增脱离请求生命周期的后台任务或盲目重试。
- 关闭表单仅停止进度查询，不中断原提交请求。查询失败由原提交请求兜底；超时保留登记编号并提示核对；同一个编号重试仍沿用幂等保护。
- 当月日历从完整月份数据推导今日与当前不在岗数据，去掉 4 个重复查询，通常 7 次查询降为 3 次；非当前月份为 5 次。保留分页、跨月请假和精确到达时刻边界。
- 刷新期间保留当前日历内容，避免提交后再次整页清空等待。
- 新增不含业务内容的阶段计时日志，供后续真实提交继续观测。

## 验证

24 项自动化回归、前后端类型检查、ESLint、生产构建通过。覆盖三种登记的并发通知、仅在写入后通知、独立失败、同一接收人去重、幂等、状态查询归属、过期未确认状态、镜像回写慢、表单关闭、查询失败、跨日/跨年、跨月及当前不在岗边界。

本地正式 SDK 联调：只读登记状态路由 HTTP 200（开发库无对应线上登记，正确返回 result=null）；真实 Base 当月数据 HTTP 200，4 个事件、8 个节假日/调休标记，耗时约 2,110 ms。这是本地到飞书的读取实测，不是线上新登记端到端性能值。

未新增真实请假/晚到/提前离开记录，未向员工发送测试消息。首次 Base 写入仍受飞书外部接口耗时影响；不能把本地测试、时序优化推算当成新的线上实测承诺。

唯一手工代码源仍为 鸭鸭日历.html；运行工程由 tools/export_runtime.py 派生。
