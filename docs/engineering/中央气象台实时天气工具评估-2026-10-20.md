# real-time-weather 对鸭鸭日历的适用性评估（2026-10-20）

评估对象：<https://github.com/zzhaoy/real-time-weather>。仅在本地临时目录克隆和测试，没有修改或部署鸭鸭日历。

## 实测结果

- 工具读取中央气象台网站 `www.nmc.cn/rest/province`、`/rest/province/{code}`、`/rest/weather?stationid=...`。这是一组网站内部接口；仓库不是中央气象台发布的官方 SDK 或正式开放 API 文档。
- `2026-10-20` 晚间，本地直接请求合肥站 `xqcji` 成功（HTTP 200，业务码 0）。初次结果发布时间 `20:05`、天气“小雨”、`rain=0.3`、西北风 `2.8 m/s`；仓库 CLI `main.py --json 合肥` 返回相同结果。20:41 左右再次查询，中央气象台发布于 `20:10` 的合肥实况仍为“小雨”、`rain=0.3`；同一时刻查询鸭鸭日历现用 MET Norway 接口，20:00 预报点为 `cloudy`、下一小时降水 `0.0`。两者分别是站点实况与模型预报，这个样本说明中央气象台的结果更符合用户所述现场下雨；单个时刻不能证明长期准确率，也不能保证瑶海区每处降雨都与合肥站一致。
- 工具查询 `瑶海区` 返回“未找到城市”；安徽站点列表有“合肥”而没有“瑶海区”。它只能代表合肥站点，不能保证瑶海区某处的局地降水。
- 仓库要求 Python 3.10+ 语法（`dict | list`）；本机默认 Python 3.9 运行报错，用 Python 3.12 和 `requests` 后测试通过。每次按城市查询时会先读取全国省份、再逐省读取城市列表；如果接入日历，应固定已核验的站点 ID 与服务端缓存，但这不解决授权问题。

## 正式使用限制

中央气象台[网站声明](https://www.nmc.cn/publish/cms/view/722665831f0a4e98800c41e691444963.html)对网站信息的第三方商业使用、转载、下载使用设有授权要求。仓库的 Apache-2.0 许可证只覆盖**工具代码**，不赋予使用中央气象台数据的授权。公司全员应用不应仅凭这个开源仓库直接长期抓取网站内部接口。

因此：此工具适合做只读技术验证或经授权后的原型参考，不宜直接替换鸭鸭日历正式天气后端。生产接入应获取中央气象台／中国天气网正式接口授权，或使用已获中国气象局数据授权、且合同覆盖公司使用的服务；若追求瑶海区降雨感知，还须验证公里级实时降水／雷达数据的时效，不能只看合肥站点天气文字。
