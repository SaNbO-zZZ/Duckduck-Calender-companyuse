## 适配和发布门槛

- 初始化后读取平台工程内的 plugin/auth/base 等领域指南，使用实际 SDK；不推测运行时接口，不在浏览器中放密钥，不使用 CLI 子进程作为运行时后端。
- 身份取自平台实际登录用户；真实人员搜索/选择返回稳定 ID。HR 从现有后台设置读取，不能只显示文本 Mia。
- 请假仍写回真实 Base。“事项、申请小时、交接说明”从用户界面删除；同时调整通知完整性条件与消息模板，避免缺少申请小时导致通知永远无法触发。后台历史列和数据不因表单删除而直接删除。
- 迟到记录当前时间及预计到达时间（当天、10:00 后且晚于当前时间），早退记录当前时间。两种动作使用明确的记录类别，不假装年假/调休，具体持久化结构在真实 SDK 与表结构核实后落地。
- 单独确定新登记的通知链路与去重状态，不通过启用旧停用工作流来无差别补发历史通知。收件人为所选 Mentor 与固定 HR，同人去重，仅通知不设置审批。
- 出勤计数使用真实数据，读取失败显示不可用，不显示虚假的“全部在岗”。
- 合肥市瑶海区天气使用可用的真实数据来源；天气类型与风独立，处理请求失败、缓存及减少动态偏好；日历使用现有完整节假日表。
- 正式入口隐藏演示控制栏及预览按钮，检查桌面/窄屏、三种登记、人员选择与 HR、数据回读、通知和权限。
- 妙搭发布必须返回正式完成状态。核实企业内部可用范围后，再切换现有企业应用主页，验证普通员工与手机入口。
