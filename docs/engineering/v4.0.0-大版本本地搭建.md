## 阶段 0 规范冻结

### 日期验收矩阵

| 场景 | 选中日期与今天关系 | 值日展示 | 动画 | 队列起点 |
| --- | --- | --- | --- | --- |
| 今天 | 同一自然日 | 当天负责人和鸭鸭 | 完整六只跟随队列 | 今天的下一星期 |
| 未来同星期 | 未来日期，星期相同 | 该星期负责人 | 仅对话动画 | 不创建队列 |
| 明天 | 未来一天 | 目标负责人 | 完整循环队列 | 目标日期次日 |
| 未来不同星期 | 未来且星期不同 | 目标负责人 | 完整循环队列 | 目标日期次日 |
| 过去日期 | 早于今天 | 值日模块隐藏负责人和鸭鸭 | 不播放 | 无 |
| 播放中改选日期 | 日历可变，舞台锁定 | 播放完成后展示最后选中的未来日期 | 当前动画不中断 | 以最终选中日期重新计算 |

所有日期以 `Asia/Shanghai` 自然日解析；节假日和周末不跳过。

### 动画状态机

`idle → reacting → walking → queueing → peek → complete → idle`。

- `idle` 只接受未来/今天目标的第一次点击。
- `reacting`、`walking`、`queueing`、`peek` 锁定舞台，重复点击不创建第二条队列。
- 播放中日历仍可发出日期选择事件，保留最后一次未来日期。
- 过去日期只更新日历选中态，不进入动画状态机。
- `prefers-reduced-motion` 或低性能模式使用静态备用图和短淡入。

### 换班状态机

`draft → awaiting_confirmation → confirmed → applied`；拒绝和取消进入 `rejected` / `cancelled`，值日当天 16:00 未确认进入 `expired`。每条请求只覆盖一个自然日，确认后才写入 `duty_override`。

### 通知异常策略

- 发送成功：记录 `accepted`，幂等键为 `beijing_date + final_person_id`。
- 明确失败：记录 `failed`，保留错误摘要，不自动重发。
- 结果不确定：记录 `needs_review`，通知管理员人工核对后再决定。
- 人员失效/离职：记录 `needs_review`，不盲目重发。
- 16:00 后确认换班：生成同一幂等键的新负责人补发任务；旧负责人不重复发送。
- 测试只使用模拟能力或受控测试收件人；真实触发器只有在用户明确授权后才启用。
