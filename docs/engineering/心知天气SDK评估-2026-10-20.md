# 心知天气 SDK 对鸭鸭日历的适用性评估（2026-10-20）

评估对象：<https://github.com/seniverse/seniverse-api>。本轮仅只读核查和无密钥连通性测试，未改动或发布鸭鸭日历。

## 结论

这个仓库是调用心知天气 API 的 Node.js/TypeScript **SDK，不是天气数据源**。仓库示例调用 `/v3/weather/now.json` 时须传账号密钥。实测不带密钥请求合肥天气，接口返回 HTTP 403、`AP010003`（API key invalid）；妙搭线上环境当前也没有心知 API 环境变量。因此无法进行“当下瑶海区是否下雨”的真实数据对照，也不能宣称已验证其准确率。

心知天气[说明其数据获中国气象局气象数据中心授权](https://docs.seniverse.com/product/service/source.html)，但它不是中国气象局直接运营的 SmartWeatherAPI。若用户接受“使用中国气象局授权数据的国内服务商”，它是候选；若严格要求直连中国气象局接口，则不符合该要求。

## 可用数据与限制

| 产品 | 对鸭鸭日历的价值 | 限制 |
| --- | --- | --- |
| [永久免费版](https://www.seniverse.com/pricing) | 国内约 370 个主要城市的天气实况；官网列 10 万次/月 | 仅城市级天气现象与气温，缺少瑶海区 1 km 降水、风速、风向；适合粗略图标，不足以修复局地雨漏报和强风动画。页面称适合个人开发者，需向供应商核实公司内网全员使用的授权。 |
| [14 天试用版](https://www.seniverse.com/pricing) | 可验证更多数据，官网列有效期 14 天、1 万次 | 不能作为长期正式天气源。 |
| [公里级网格实况](https://docs.seniverse.com/api/grid/now.html) | 按瑶海区坐标返回 1 km 网格天气、近一小时降水 `precip`、风速和风向 | 属高精度产品，需取得对应产品权限与商业条件。旧[更新频率文档](https://docs.seniverse.com/product/other/lag.html)称约 1 小时更新、1 小时滞后，因此单靠它仍可能漏掉刚开始的雨。 |
| [分钟级降水预报](https://docs.seniverse.com/api/weather/minutely.html) | 1 km 网格，返回当前分钟及后续分钟的降水强度序列 | 属预报，仍须和实况配合；需产品权限。供应商[产品页](https://www.seniverse.com/buy)称每 6 分钟更新，旧[更新频率文档](https://docs.seniverse.com/product/other/lag.html)称约 10 分钟更新、5 分钟滞后，实际时效须用授权账号实测。 |

## 工程建议

若取得高精度产品权限，用**服务端**按固定瑶海区经纬度请求公里级网格实况，并向供应商确认是否可接[雷达降水实况](https://www.seniverse.com/api)或极速实况，以更及时地判断刚开始的雨；分钟级降水预报提供雨势趋势。风速、风向仍由实况驱动，与晴／阴／雨／雪环境独立。检查 `last_update`，过期时明确显示“天气暂不可用”。根据实际数据更新频率调低现有 30 分钟服务端缓存与前端轮询，同时让全员共享服务端缓存，避免每位员工独立消耗 API 配额。密钥仅放妙搭线上环境变量。

仓库当前 `package.json` 为 SDK 0.1.2，最近 Git 提交为 2019-11-02，依赖旧版 `request` 和 `request-promise`；当前鸭鸭日历后端已有原生 `fetch`，获得密钥后可直接调用官方 REST API，未必需要引入此 SDK。无账号和产品权限前，不应将它接入正式应用，也无法量化比现有 MET Norway 逐小时预报准确多少。
