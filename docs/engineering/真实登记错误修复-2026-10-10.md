# 首笔真实登记错误修复

用户在飞书提交「天才总是晚到」，服务器返回 HTTP 500。

## 根因与影响

日志确认：登记幂等表 calendar_submission 的 INSERT 没有写 `_created_by`，该列没有默认值；员工行级权限规则要求创建人与当前请求身份一致，因此 PostgreSQL 拒绝写入（42501）。首笔请求未建立数据库登记，按代码执行顺序尚未写入多维表格或发送通知。

## 修复与验证

- 仅在主文件「鸭鸭日历.html」中的后端适配代码补上 createdBy、updatedBy，取值来自服务端已认证的 userId。派生工程由 tools/export_runtime.py 重新导出。
- 没有修改数据库结构、行级权限、可用范围或人员配置。
- 新增回归测试检查遗漏创建人会被拒绝，并验证实际 Drizzle 生成 SQL 包含两个审计人员字段；共 7 项通过。
- 前后端 typecheck、ESLint、服务端和客户端构建通过。
- 线上数据库使用 SDK 实际使用的 authenticated_<schema> 员工角色、真实当前用户，在事务中验证：原始写法被 RLS 拒绝；修复写法可以插入并读取本人行。全部回滚，回读探针行数为 0，没有保留测试业务记录或发送测试通知。最初使用通用 authenticated 角色的诊断未模拟该应用实际角色，已纠正，不能当作修复验证结论。
- 插件曾出现 fetch failed 网络错误；最近 5 分钟错误日志为空。实际登记恢复时继续核验，不能将其直接归为已修复。
