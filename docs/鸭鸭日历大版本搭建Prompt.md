# 鸭鸭日历大版本更新：本地妙搭搭建 Prompt

你现在负责在本地对已有飞书妙搭应用“鸭鸭日历”进行大版本功能搭建。

这不是普通网页项目，也不是独立静态网站。必须遵循飞书妙搭的本地开发、应用运行时、插件、数据库、自动化任务和发布逻辑。所有代码必须能够在妙搭应用工程中运行，并通过妙搭的 Git 与 release 链路更新现有应用。

## 二、妙搭工程边界

- 目标应用是已有妙搭应用，应用 ID 为 `app_17fstqsqv1c`，不要创建新应用。
- 先确认当前目录是否是这个妙搭应用的本地初始化工程，检查 `.spark/meta.json`、远端地址、分支和项目结构。
- 如果当前目录只是 GitHub 镜像或设计工作区，不要直接把它当作妙搭工程发布；按妙搭本地开发流程定位现有应用并使用 `+init` 或受支持的 Git 初始化方式取得正确的本地工程。
- 代码开发使用妙搭工程的本地分支，遵循 `sprint/default`、commit、push、release 的平台约定；不要直接向发布态 `main` 推送。
- 不使用 `lark-cli` 子进程作为应用运行时代码。
- 不把飞书 token、App Secret、员工名单、open_id 快照、环境变量、授权文件或真实业务数据写入 Git。
- 图片、字体、音视频等资源属于妙搭应用文件存储资源，不要直接提交到 Git、引用本地路径或以 base64 内嵌；按妙搭文件存储指南上传并使用受支持的资源 URL/manifest。
- 不使用外部托管、Vercel、Netlify、GitHub Pages、个人服务器或独立数据库。
- 没有明确发布授权前，不执行 `+release-create`、`+automation-enable`、主页切换、权限变更或真实员工通知。
- 自动化触发器创建后保持 disabled，直到用户明确要求启动。

## 四、红框舞台和日期规则

默认状态：

- 展示当天值日鸭鸭；
- 鸭鸭下方展示负责人姓名；
- 展示“今天是周几，轮到你铲屎了”一类提示；
- 舞台支持桌面、手机和低性能降级。

点击规则：

1. 点击当天鸭鸭：鸭鸭完成点击反应，向左水平走出；随后本轮日期之后的其他六只鸭鸭按星期顺序依次跟随出现；最终最初鸭鸭探头并跳出。
2. 点击未来日期且星期与今天相同，例如今天周六、点击下周六：不播放队列，只播放该鸭鸭的对话动画，例如“我记得，我会好好铲屎”。
3. 点击明天或下周其他星期的未来日期：播放完整循环队列，队列从被查看日期的下一天开始，循环展示其余六只鸭鸭。
4. 周日也必须执行完整循环：周日之后依次为周一、周二、周三、周四、周五、周六。
5. 点击过去日期：值日模块不显示历史负责人，也不播放历史值日动画；现有请假、晚到、早退历史记录不得被删除或过滤。
6. 同一只鸭鸭连续点击多次时，舞台锁定到本轮播放完成，不重复创建队列、不叠加动作。
7. 动画期间锁定舞台交互。日历可以改变选中日期，但当前动画不被打断；动画结束后，舞台只展示最后一次选中的未来日期。
8. 所有日期判断使用 `Asia/Shanghai`，按自然日执行，不跳过周末或节假日。

请把以上规则实现为明确的日期解析函数、队列计算函数和动画状态机，并为周一至周日全部起点建立测试。

## 五、2.5D 鸭鸭素材要求

最终为七只鸭鸭分别制作统一风格的 36 个方向待机图，约每 10 度一个视角。

36 个方向图只负责待机多视角，不代替动作帧。每只鸭鸭还需要：

- 点击反应；
- 向左行走循环；
- 探头；
- 跳出；
- 缩略图；
- 静态备用图。

素材统一要求：

- 相机角度、光照、材质、比例、阴影和透明背景一致；
- 七只鸭鸭可以通过颜色、配件和性格区分，但不能改变整体美术系统；
- 先完成一只鸭鸭的视觉样板，验证 36 方向、动作帧、文件尺寸、透明背景、加载速度和移动端表现；
- 样板通过后再批量制作另外六只；
- 生成素材前形成角色设定表，包含颜色、配件、性格关键词和禁止元素；
- 使用版本化资源 manifest，支持缓存失效和静态备用图；
- 资源上传妙搭应用文件存储，不将大量图片内嵌到源码或提交 Git。

## 六、每天 16:00 通知

每天北京时间 16:00 向当天最终负责人发送私聊提醒。

规划 Cron：`0 16 * * *`，时区 `Asia/Shanghai`。

运行时流程：

1. 读取当前北京时间日期和星期；
2. 读取固定周排班；
3. 读取当天指定日期临时换班；
4. 按覆盖优先级解析最终负责人；
5. 调用妙搭支持的飞书消息能力发送私聊；
6. 使用“日期 + 最终负责人”作为幂等键；
7. 持久化受理、失败、待核对状态。

通知边界：

- 人员 ID 无效、人员离职或通知结果不确定时，不盲目重发；记录待核对状态并通知管理员。
- 当天 16:00 之后确认的换班，需要立即向新负责人补发当日提醒。
- 通知正文至少包含日期、星期、负责人、铲屎提醒和鸭鸭日历入口。
- 测试阶段使用受控测试收件人或模拟能力，不直接向全员发送真实消息。

## 七、临时换班机器人

使用应用机器人，不使用只能向群推送的自定义机器人。

流程：

1. 用户向“值日换班助手”发送“我要换班”；
2. 机器人询问具体日期；
3. 机器人列出可选交换对象；
4. 对方收到确认卡片；
5. 对方确认后才建立临时换班；
6. 对方拒绝、请求过期或发起人取消时，不改变最终排班；
7. 双方收到结果通知；
8. 换班记录保留原负责人、新负责人、日期、发起人、确认人、状态、创建时间和确认时间。

换班权限：

- 普通员工只能发起涉及自己的换班；
- 被邀请人只能确认或拒绝；
- 管理员可以编辑固定排班、取消临时换班和处理异常；
- 固定排班变化必须设置生效日期，不得悄悄改写历史日期；
- 未确认请求在值日当天 16:00 自动失效；
- 不允许一条未确认请求同时覆盖多个日期；
- 收到消息和卡片回调都要做事件幂等，不能重复创建换班。

如果妙搭当前运行时无法接收入站单聊或卡片回调，不要伪造接口或改用普通网页轮询；先报告能力缺口和需要的官方配置/权限。

## 八、与现有工程的集成要求

当前工程是 React 页面外壳、iframe 日历文档和 NestJS 服务端组合。

- 值日功能必须同时进入前端舞台、服务端日期解析、数据库、资源 manifest 和通知/机器人接口。
- `client/src/pages/Calendar/calendar-document.ts` 是生成文件，不能直接作为唯一手工源文件编辑；先确认规范源文件和导出链路。
- 复用现有 `/api/calendar/sprites` 资源读取模式、文件存储和缓存策略，但要为 36 方向和动作素材增加版本化 manifest。
- 复用已有的出站 `send-feishu-message` 能力时，按项目插件指南和实际类型实现；不要猜测参数结构。
- 数据库变更按妙搭支持的迁移/执行方式完成，使用平台规定的审计列、RLS 和环境边界。
- 不要破坏现有请假、调休、晚到、早退、天气、法定节假日和已有通知流程。

## 九、分阶段实施顺序

### 阶段 0：规范冻结

交付：日期验收矩阵、动画状态机、换班状态机、权限矩阵、通知异常策略、角色设定表模板。

没有完成阶段 0，不进入业务编码。

### 阶段 1：一只鸭鸭视觉样板

交付：一只鸭鸭的 36 方向待机图和全部动作帧；完成桌面、手机、低性能和静态备用验证。

样板未通过，不批量生成另外六只。

### 阶段 2：七只鸭鸭资产包

交付：七只鸭鸭的统一资源 manifest、36 方向图、动作帧、缩略图、备用图，并上传妙搭应用文件存储。

### 阶段 3：值日业务后端

交付：数据库表、RLS/权限、固定排班、临时覆盖、人员绑定、换班状态和通知投递状态；实现日期解析与循环队列服务。

### 阶段 4：值日舞台前端

交付：红框舞台、姓名和文案、日期联动、队列动画、交互锁、未来/过去规则、移动端和减少动态模式。

### 阶段 5：16:00 定时提醒

交付：定时 handler、动态收件人解析、通知幂等、异常状态和受控测试。

创建触发器后保持 disabled，未发布前不要启用。

### 阶段 6：换班机器人

交付：单聊接收、卡片选择、双方确认、过期、拒绝、取消、审计和结果通知；网页提供换班入口。

### 阶段 7：验证和发布

交付：类型检查、Lint、构建、业务单元测试、通知幂等测试、动画截图/录像、桌面和手机验证、减少动态验证、机器人回调验证和发布记录。

只有用户明确要求上线时，才执行 commit、push、release、触发器 enable 或真实消息验证。
