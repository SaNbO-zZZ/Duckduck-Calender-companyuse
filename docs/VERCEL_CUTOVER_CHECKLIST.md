# 鸭鸭日历预发与切流验收

正式入口为 `https://calendar.alphapulsex.online`。迁移目标时间为 2026-11-28 23:59:59（北京时间）。采用逐项核对和批准的方式推进。每一项记下验证日期、提交 SHA、页面或请求证据和批准人。

## 预发准备

1. 在目标 Vercel 团队确认项目及 Production Branch。用迁移分支部署 **Preview**，记录不可变部署 URL、提交 SHA 与 `Ready` 状态。构建使用 `npm ci --include=dev` 和 `npm run build:client`，输出 `dist/client`。本地 CLI 上传以干净的 Git 快照为输入。
2. 给预发选定稳定地址，配置 Preview 的 `APP_BASE_URL` 及其飞书 OAuth 回调，校验入口和回调同源。飞书内访问若被 Vercel Deployment Protection 拦截，使用团队允许的预发访问方式，保持预发的企业 OAuth 和只读限制。
3. 将飞书和 Supabase 服务凭证按 [环境变量模板](../.env.example) 放到对应服务的安全配置，签发独立的预发会话密钥。用已导入的企业账号登录。先验证未登录业务请求为 401、登录后月历和公约可读、预发写入为 403。使用 `GET /api/cron/duty-reminder?dryRun=1` 加调度凭证核对收件人解析。
4. 用独立夹具验证写入和发送合约。真实登记、换班、已阅确认和消息触达需要记录指定测试账号及已批准的范围。

## 正式切流顺序

1. 取得逐项审批，记录固定域名当前 DNS、飞书原主页及导航、已验证的旧 release 和两边的调度状态。在切流窗口重新导出妙搭九张表，核对行内容、人员映射和审批中的换班，避免仅靠计数判断增量。先备份目标数据，以受审方式补齐变更并再次比对。已完成的历史快照复查仍需在窗口内重跑。
2. 配好 Production 环境，使用 Vercel 给出的 DNS 目标为 `calendar` 设置 CNAME 并确认 HTTPS。核对生产回调及登录态。记录 Vercel 部署 ID，检查登录、公约、登记和换班深链。
3. 在北京时间 16:00 调度窗口之外交接提醒。确认 Vault 中 `ducky_cron_secret` 和生产 `CRON_SECRET` 对应，先以 `dryRun=1` 验证，再停妙搭 `duty16hReminder` 并回读状态，最后启用 Supabase `ducky-duty-reminder-1600`（UTC 08:00）。检查下一次执行和投递记录，核对收件到达时间。
4. 切换飞书两端主页和公司电脑导航。由批准人使用飞书两端真机核对新入口，记录正式部署及切流时间。节日上线与全员版本知会按各自授权执行。

## 回退

先暂停新调度并回读状态，保全新系统的登记、换班和投递记录。确认当天无重复投递风险后，再恢复妙搭调度。恢复已记录的飞书两端主页及原导航。若已发生新系统写入，先核对原多维表格记录和 Supabase 幂等、换班及投递状态，再补偿差异。记录回退时间、入口、调度状态与用户验收结果。
